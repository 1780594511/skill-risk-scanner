# Skill Risk Scanner · 第三方 Skill 接入风险初筛助手

An offline, explainable static triage tool for reviewing local Agent Skill directories before adoption. Built with Python's standard library; it never imports, installs, or runs the inspected content.

面向第三方 Skill 接入前的人工风险复核，识别网络调用、命令执行、凭据访问和简单下载执行组合。报告提供文件/行号、上下文、潜在影响、证据置信度、例外理由及覆盖缺口；不提供“绝对安全”或“确定恶意”的二元判定。

## What is implemented

- 8 explainable rules using Python AST plus deliberately limited shell/PowerShell/text patterns.
- A local CLI with JSON and Markdown reports; no network calls or remote models at scan time.
- Bounded file reads, link/reparse exclusions, sensitive-file exclusions, conservative snippets, and escaped report rendering.
- Exact, reasoned, expiring exceptions that retain findings and do not waive unrelated rules.
- 24 synthetic Skill fixtures with an independently written manifest covering 42 expected rule locations.
- A project-local Agent Skill wrapper that calls the same scanner implementation; not globally installed.

## Quick start · Windows / PowerShell

Python 3.12 is the verified environment. After cloning or extracting this repository, run from its trusted root directory:

```powershell
python -m venv .venv
$env:PATH = (Resolve-Path '.venv\Scripts').Path + ';' + $env:PATH
$env:PYTHONUTF8 = '1'
python -m pip install -r requirements-dev.txt
python -m skill_guard demo
```

The scanner itself has **no third-party runtime dependencies**. Installing pytest needs a package source; scanning does not need network access. PyYAML is only used by the host-specific Skill format validator and is not required by `skill_guard`.

Demo exits with **3**, because it intentionally includes findings requiring human review. Do not execute fixture scripts; they are text inputs for the scanner. Always run the CLI from this trusted repository, not from the inspected directory, to avoid module shadowing.

```powershell
python -m skill_guard scan fixtures\18_risky_skill --config configs\default.json --out reports\manual-risk
python -m skill_guard evaluate --fixtures fixtures --out reports\evaluation
python -m pytest
python scripts\verify.py
```

Replace the fixture path with an explicitly selected local Skill directory. `--out` must be empty or previously generated by this scanner, and cannot equal or contain the input directory. No input directory is selected by default.

Evidence files are snapshots of actual local runs. Machine paths and the JUnit hostname are explicitly normalized for publication; counts, test outcomes, skip reasons, and timestamps are preserved. Runtime outputs live in ignored `reports/`; committed snapshots live in `examples/` and `evidence/`.

The 24 synthetic cases have 42 expected rule locations. TP/FP/FN use the tuple `(case, rule_id, relative_path, 1-based line, context)`. This is a small functional benchmark, **not a real-world malicious Skill detection rate**. See [STATUS](STATUS.md) for the measured test count and environment-specific skips.

## Exit codes

| Code | Meaning |
| --- | --- |
| 0 | scan/demo: declared scope complete and no outstanding review findings; informational findings/exceptions may remain. evaluate: expectations matched. |
| 1 | evaluate: mismatch with the handwritten manifest. pytest uses its own exit codes. |
| 2 | CLI input, configuration, path, or output error. |
| 3 | Complete declared scope, with findings needing human review. |
| 4 | Coverage incomplete; this takes precedence over 3, with findings retained. |

Code 0 is not security certification. Skipped directories are not enumerated recursively, so their child-file counts are unknown and are not invented.

## Configuration

See `configs/default.json` and `configs/reviewed-example.json`. Trusted code implements the rules; JSON controls limits, disabled rules, exact host exceptions, precise rule/path/line exceptions, and report settings. Target-side configs are never loaded as scanner configuration.

Default limits: 256 KiB/file, 1000 candidate files, 8 MiB total reads, 10000 entries, and 32 directory levels. Domain exceptions affect only SG001/SG002 for a unique literal host; they never waive execution or credential rules. Invalid and expired exceptions fail validation. The examples pin `reference_date` to 2026-11-08 for reproducibility; for a new review, use its actual date or omit that field to use the current UTC date.

Raw source snippets are disabled by default. If enabled, only a fixed-vocabulary token skeleton is emitted; strings, unknown identifiers, and URL query values are omitted. Exception reasons must not contain secrets. Reports still include relative paths and known hostnames, so review them before sharing.

## Scope and limitations

Supported: `.md`/`SKILL.md`, `.py`, `.sh`, `.ps1`, plus `.json/.yaml/.yml` as plain text. Markdown code fences are labelled as documentation examples. JavaScript/TypeScript and other file types are reported as uncovered.

This is not a sandbox or an automatic malware verdict. It does not provide dynamic analysis, full shell parsing, complete alias/scope resolution, cross-file taint analysis, deobfuscation, redirect tracking, or protection against adversarial filesystem races. `shell=True` does not alone prove command injection; environment access does not alone prove data leakage. Findings indicate review questions.

Symbolic links/reparse points, hard links, dependency directories, real `.env` files, and common credential files are skipped. The only tracked `.env` is an explicitly whitelisted synthetic fixture. Git's reserved `.git` directory is created only inside a temporary test directory, never stored as fixture repository metadata.
